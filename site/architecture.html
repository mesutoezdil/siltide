How a number gets on the screen

Every value siltide shows is measured, derived, or missing, and it says which. This is the path from a device to a cell in a table.

1. DetectEach vendor is probed once at startup: a library load, a PATH lookup, a sysfs stat. What answers is collected from; what does not is listed with the hint for installing it.
2. CollectEvery active provider is read in parallel on the refresh interval, each with a timeout, so one slow vendor tool cannot hold up the rest.
3. EnrichProcesses gain their command, user and container from /proc, then their pod, namespace and workload from Kubernetes, and their job from Slurm.
4. DeriveStates, outliers, idle-allocated devices, health scores and fleet totals are computed from measured values, and are labelled as derived wherever they appear.
5. RecordOne point per device per resolution goes to an hourly plain-text file with a checksum per line, which is what the time machine reads back.
6. ServeThe interface, the JSON API, the Prometheus endpoint and the MCP server all read that one snapshot. What you see is what they serve.

The rule underneath

A metric a vendor did not report is N/A, never zero. A value siltide worked out rather than read is marked derived. A device that answered nothing is down rather than idle. The point of a monitor is to be believable when it is inconvenient.
